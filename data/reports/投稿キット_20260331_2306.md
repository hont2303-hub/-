## テクニック1：曖昧な仕様をそのままぶつけて、要件定義を一緒に整理する

### Before：仕様整理だけで2時間消えていた

新しい機能開発を始めるとき、まず「何を作るか」を明確にする必要があります。しかし、顧客やPMから来る仕様はしばしば曖昧です。「ユーザーが使いやすいログイン機能を作って」という指示から、実装に入れるレベルまで落とし込むのに、以前は1〜2時間かかることも珍しくありませんでした。

### After：20分で実装タスクリストが完成

Claude Codeに仕様書のテキストをそのまま貼り付けて、こう聞きます。

```
以下の仕様を読んで、実装すべき機能を箇条書きにして。
曖昧な部分は「確認が必要な点」として別途まとめて。

【仕様】
ユーザーが使いやすいログイン機能を作る。
SNSログインも対応させたい。セキュリティも重要。
```

すると、Claude Codeは以下のように整理してくれます。

- メール/パスワードによる基本認証
- Google / GitHub OAuthによるソーシャルログイン
- JWTトークンによるセッション管理
- パスワードリセット機能
- ログイン試行回数の制限（ブルートフォース対策）

**確認が必要な点：**
- パスワードの最小文字数・複雑さ要件は？
- セッションの有効期限は何時間か？
- 2要素認証（2FA）は必要か？

これをたたき台にPMに確認を取れば、認識のズレを早期に潰せます。仕様整理の時間が**2時間→20分**に短縮されました。

## テクニック2：「このコードを直して」ではなく「なぜ壊れているか教えて」

### Before：エラーメッセージをひたすらGoogle検索

バグに遭遇したとき、以前はエラーメッセージをコピーしてGoogle検索→Stack Overflowをさまよう、という流れが定番でした。同じエラーでも文脈が違えば解決策も違うため、ヒットした記事が自分のケースに当てはまらないことも多く、30分〜1時間溶けることがザラでした。

### After：原因理解ごとセットで5分解決

Claude Codeへのプロンプトのコツは「直してほしい」ではなく「**なぜ壊れているか説明してほしい**」と聞くことです。

```bash
# ターミナルでClaude Codeを起動した状態で：

```

```

## テクニック3：テストコードの自動生成で品質担保と時短を同時に実現

### Before：テスト書くのが後回しになりがち

「テストは大事とわかっているけど時間がない」。これはエンジニア界隈の永遠の課題です。実装で力を使い果たし、テストコードを書く気力が残らない。そして後でバグが発生して余計に時間を取られる、という悪循環。

### After：実装と同時にテストも生成

実装が完了したら、即座にClaude Codeに投げます。

```
以下の関数のユニットテストをJestで書いてください。
正常系・異常系・エッジケースを網羅してください。

function calculateDiscount(price, memberRank) {
  if (price <= 0) throw new Error('Price must be positive');
  
  const discountRates = {
    gold: 0.2,
    silver: 0.1,
    bronze: 0.05,
    normal: 0
  };
  
  const rate = discountRates[memberRank] ?? 0;
  return Math.floor(price * (1 - rate));
}
```

Claude Codeは以下のようなテストを自動生成します。

```javascript
describe('calculateDiscount', () => {
  // 正常系
  test('ゴールド会員は20%割引される', () => {
    expect(calculateDiscount(1000, 'gold')).toBe(800);
  });

  test('シルバー会員は10%割引される', () => {
    expect(calculateDiscount(1000, 'silver')).toBe(900);
  });

  // 異常系
  test('価格が0以下の場合はエラーをスローする', () => {
    expect(() => calculateDiscount(0, 'gold')).toThrow('Price must be positive');
    expect(() => calculateDiscount(-100, 'gold')).toThrow('Price must be positive');
  });

  // エッジケース
  test('未定義の会員ランクは割引なし', () => {
    expect(calculateDiscount(1000, 'platinum')).toBe(1000);
  });

  test('小数点以下は切り捨てられる', () => {
    expect(calculateDiscount(999, 'bronze')).toBe(949); // 999 * 0.95 = 949.05
  });
});
```

テストコード作成時間が**30分→5分**になりました。しかもClaude Codeはエッジケースを人間が見落としがちな視点から指摘してくれるため、品質も上がります。

### After：レビュー前にAIでセルフチェック

## 5つのテクニックを最大限活かすためのTips

### プロンプトに「文脈」を与える

Claude Codeは文脈を理解することで精度が上がります。単に「コードを書いて」ではなく、「このプロジェクトはNext.js 14 + TypeScript + Prismaを使っています。以下の要件で〜」のように背景情報を与えましょう。

### CLAUDE.mdでプロジェクト設定を共有する

プロジェクトルートに`CLAUDE.md`ファイルを置くと、Claude Codeが自動的に読み込みます。プロジェクトの技術スタック、コーディング規約、よく使うコマンドをここに書いておくと、毎回説明する手間が省けます。

```markdown
# プロジェクト概要
このプロジェクトはECサイトのバックエンドAPIです。

## 技術スタック
- Node.js 20 + TypeScript
- Express.js
- PostgreSQL + Prisma ORM

## コーディング規約
- 関数はすべてJSDocコメントを付ける
- エラーハンドリングは必ずtry-catchで行う
- 変数名は英語、日本語コメントOK
```

### アウトプットの形式を指定する

「箇条書きで」「表形式で」「コードブロックのみで」など、出力形式を指定するとそのまま使えるアウトプットが得られやすくなります。
